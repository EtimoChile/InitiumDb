| DEC-002 | ACTIVE | Java 25 / Maven stack, engine-independent core | `core/` free of engine-specific SQL/driver types (standard JDBC allowed), `db/<engine>/` minimal adapters. Maven, Java 25 (LTS) baseline. Base package `cl.etimo.initiumdb`, Maven `groupId` `cl.etimo` (set by the owner). Engine names follow the industry name: `oracle`, `postgresql` (tags `<engine>_integration`). Exit codes: `0` success, `1` failure. | `pom.xml`, `AGENTS.md`, `README.md`, `src/main/java/cl/etimo/initiumdb/` | — |
| DEC-003 | ACTIVE | `idb-init` and `idb-crypt` | Replaces the README's "two executables only" with four. `--case`/`--environment` select the case and environment. Local secrets: `<config-dir>/<env>.secrets.json` (default `~/.initiumdb`), AES-256-GCM tokens, key from `IDB_MASTER_KEY` or `~/.initiumdb/idb.key`. A missing secrets file fails; commands that read cleartext values encrypt them in place; `idb-init` never overwrites existing entries; no `--log-level`. Local encryption is one provider, not the only one (see PEND-005). | `README.md`, `cli.IdbInit`, `cli.IdbCrypt`, `core.SecretCipher`, `core.MasterKey`, `core.SecretsFile` | Add `idb-init` and `idb-crypt` commands. |
| DEC-004 | ACTIVE | Thin per-engine profile | Each engine is a minimal `DatabaseEngine` (`name`, `configure(DatabaseConfig)`, `useSchema`): it sets the DBUnit `IDataTypeFactory` and properties and the session schema; `Engines` resolves it by name. No adapter hierarchy. Reconsider only for an engine DBUnit cannot cover through `DatabaseConfig`, or for logic that is not configuration. | `db/DatabaseEngine`, `db/Engines`, `OracleEngine`, `PostgresqlEngine` | Add per-engine profiles for Oracle and PostgreSQL. |
| DEC-005 | ACTIVE | Object names exact, SQL by engine rules | Fields naming objects (`schema`, `tables[].name`) are used exactly as written (same case as the data dictionary); the session schema is double-quoted. `sql`/`preSql`/`postSql` go to the engine unchanged. A table without `sql` is captured with `SELECT * FROM <quoted name>` (the name is an object name, so it is double-quoted). DBUnit runs with `escapePattern` `"?"` and case-sensitive table names. DBUnit folds the schema name in `DatabaseConnection` (`SQLHelper.correctCase`), so `DbUnitSession` returns the exact schema from `getSchema()`. Verified with opt-in container tests (Docker). | `README.md`, `db/SqlIdentifiers`, `OracleEngine`, `PostgresqlEngine`, `integration/*RoundTripTest` | Use object names exactly as written; quote the session schema. |
| DEC-006 | ACTIVE | Prepare runs in autocommit; dataset in one transaction | `idb-prepare` is recovered by re-running it from the first step, so manual commit boundaries add nothing and make hook behavior depend on the engine (Oracle DDL commits implicitly). `preSql`/`postSql` run in autocommit as written. DBUnit `REFRESH` runs statement by statement (verified in 3.0.0), so under autocommit it would commit per row; it is applied in one short transaction instead (no user SQL inside). Hooks must be idempotent (README). | `README.md`, `core/PrepareService`, `PrepareTest` | Run SQL hooks in autocommit and apply the dataset in a single transaction. |
| DEC-007 | ACTIVE | SQL hooks are plain statements, no procedural blocks | A hook script is a sequence of SQL statements ending in `;`. InitiumDb does not parse or run procedural blocks (PL/SQL, `DO $$ ... $$`): that would make it a scripting runtime and tie hooks to each engine's procedural dialect. Hooks stay declarative; repeatability comes from idempotent statements (DEC-006). Conditional execution is a small notation over plain statements, not procedural code (DEC-010). | `README.md`, `core/SqlScript` | — |
| DEC-008 | ACTIVE | Folder distribution with launcher scripts | `maven-assembly-plugin` (phase `package`) builds `bin/` (four `idb-*` launchers, shell and `.cmd`, using `JAVA_HOME` or `java` from `PATH`) and `lib/` (project jar plus runtime jars) and an empty `drivers/` as zip, tar.gz and a folder. JDBC drivers are not bundled (`provided` scope): the user supplies them, so Oracle and other non-Apache licenses are never redistributed. A fat jar was rejected for the same reason. | `pom.xml`, `src/assembly/dist.xml`, `src/main/dist/bin/`, `DistributionIT` | Package the four commands as a folder distribution with launcher scripts. |
| DEC-009 | ACTIVE | A case is a directory; file names are fixed by convention | `--case` names a directory whose name is the case name. It holds `case.yml` (`version`, ordered `databases: [{alias}]`) and, per alias, `<ALIAS>.queries.yml`, `<ALIAS>.dataset.xml` and the optional hooks `<ALIAS>.pre.sql` / `<ALIAS>.post.sql` (absent or empty run nothing). No path or boolean fields: `idb-init` always knows the files, never leaves orphans and can complete the files of an existing alias. Shared hooks and several hooks per alias are given up; two cases cannot share files (one directory each). Chosen over per-step path fields and over booleans for hooks. | `README.md`, `core/CaseConfig`, `core/ProjectInitializer`, `PrepareService`, `CaptureService` | Breaking: a case is a directory with fixed file names. |
| DEC-010 | ACTIVE | Conditional statements are `idb:` directives in line comments | Inside a hook, `-- idb:run-if <query>` or `-- idb:skip-if <query>` before a statement runs it only if the guard returns (run-if) or does not return (skip-if) a row; the guard is the rest of the line; one directive per statement, no nesting or `else`; the directive line is not sent to the database. Chosen over `@`-prefixed directives (`@file` means "run script" in SQL*Plus, and the file stops being plain SQL) and over case-level `runIf` fields (conditions belong per statement). The `.sql` stays valid SQL for other tools. Because a typo would silently run a non-idempotent statement, any `-- idb:` comment must be a valid directive, otherwise the run fails before any hook of the step runs. Other comments, including block comments, have no meaning and are kept as written. | `README.md`, `core/SqlScript`, `PrepareService`, `PrepareTest` | Add conditional SQL statements with `-- idb:run-if` and `-- idb:skip-if`. |
